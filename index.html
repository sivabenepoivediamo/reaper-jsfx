reaper jsfx

Experiments with JSFX, REAPER's scripting format for audio and MIDI effects. Two MIDI harmony tools and three pedal-inspired audio effects, each in a single file you can copy into REAPER.

This is a personal playground, so expect rough edges. Ideas and bug reports are welcome: open an issue if something sounds wrong.

Install

  1. Get the .jsfx files you want from the Download tab or from each effect's tab.
  2. In REAPER, open Options > Show REAPER resource path in explorer/finder.
  3. Copy the files into the Effects folder (or a subfolder of it).
  4. In the FX browser press F5 to refresh, or restart REAPER.
  5. Add the effect to a track. MIDI effects go on a track before the instrument and are meant to work with realtime polyphonic MIDI input. Audio effects go on a track with some audio content.

REAPER stores slider values with the project and with FX presets. If you change defaults in a file and an old instance still shows the old values, add a fresh instance. Reordering sliders changes how saved presets and automation map to controls.

Block Chords

Turns single-note melodies into block chords. Every note you play is treated as the top voice of the melody. A port of the "blockchords" web tool.

Download Block Chords.jsfx
User manual

Quick start

  1. Put the effect on a MIDI track, before your instrument.
  2. Pick a root, a scale and a base shape.
  3. Play single notes. Each one comes out as a chord.

How a note is harmonized

  • Notes in the base shape use the inversion of that shape that puts the melody note on top.
  • Other scale degrees get descending thirds along the scale. A voice that would form a tritone with the melody moves up one scale step.
  • Notes outside both are treated as a chromatic alteration of the nearest in-scale note. You choose whether the whole chord moves with it or only the melody note.
  • Bass doubling adds the melody an octave below. Drop 2 / 3 / 4 move the second, third or fourth voice an octave below that doubling.

Overlapping chords share notes safely: releasing one chord never cuts a note another chord still holds. Notes outside the harmonize range pass through unchanged.

Developer notes
  • Slider map: 1 root, 2 scale category, 3 to 14 one picker per scale category (12 groups, SB = 3), 15 to 26 custom scale toggles (CSB = 15), 27 shape category (CGRP), 28 to 38 one picker per shape category (HB = 28), 39 to 50 custom shape toggles (CHB = 39), 51 to 53 drops, 54 transpose, 55 bass doubling, 56 velocity, 57 and 58 range. @slider hides the pickers that do not apply with slider_show.
  • Library format: each scale or shape is a 12-bit mask (bit b set means b semitones above the root). Masks are loaded with ls() and lh() in @init into LS (1000) and LH (2000). GSS[] and GSC[] hold the first library index of each category.
  • Adding a scale: insert the mask with ls() at the end of its category, shift the later GSS entries, then raise that picker's slider range and add its name in the slider definition. The list order must match the mask order.
  • Core functions: harm_shape() builds the inversion with the melody on top. step_scale() moves a note by scale steps and returns -9999 if the note is not in the scale. harmonize() assembles OUT[] including alteration, bass doubling and drops.
  • Note bookkeeping: CNT[ch*128+note] counts the chord notes per held input note. STORE keeps up to 8 output pitches per input note. REFC reference-counts output pitches: a note-on resends a note-off first if the count is above 0, and a note-off is sent only when the count returns to 0. CC 120 and 123 clear the counters for that channel.
  • Named strings are not accessible inside functions, so string handles (NMS, CHS) are assigned in @init and used as globals.

Maestro FZ-1 Fuzz-Tone

A stereo fuzz inspired by the Maestro FZ-1. The two channels are processed independently, so it works on mono or stereo tracks.

Download Maestro FZ-1 Fuzz Tone.jsfx
User manual

Quick start

  1. Put it on an audio track, ideally first in the chain so it sees the raw instrument.
  2. Set Fuzz for the amount and Volume to match your level.
  3. Shape the sound with Bias, Tone and Sag.

Controls

ControlRangeWhat it does
Fuzz0 to 100Drive. Raises the first-stage gain from -6 dB to +44 dB and lowers the pre-clip low-pass from 9 kHz to 4 kHz.
Volume (dB)-40 to +12Level of the processed signal.
Bias0 to 100DC offset ahead of the clippers, for more asymmetric clipping. High settings get ragged and can starve the signal.
Tone0 to 100Output low-pass from about 1 kHz to 12 kHz.
Sag0 to 100Level-dependent bias drop in the second stage. Loud passages compress and thin out, and notes can sputter as they decay.
Mix (%)0 to 100Dry/wet blend. Volume only affects the wet signal.

Defaults: Fuzz 60, Volume -12 dB, Bias 35, Tone 50, Sag 25, Mix 100.

Signal path

90 Hz input high-pass, first clipper, 250 Hz coupling high-pass, a low-pass that darkens with Fuzz, a second clipper with envelope-driven bias sag (about 2 ms attack, 150 ms release), tone low-pass, 20 Hz DC blocker. Both clippers are asymmetric: the positive half clips softly and the negative half has a lower ceiling, which adds even-order harmonics. The fuzz path runs at 2x oversampling.

Developer notes
  • Sliders: 1 Fuzz, 2 Volume, 3 Bias, 4 Tone, 5 Sag, 6 Mix. All coefficients are computed in @slider at twice the sample rate (fs2 = 2*srate).
  • Structure: fz() is an instance function (state in z1..z5, env). Each channel is an instance (chL, chR) configured by fz_set(). Parameters are passed as arguments so both channels share the same coefficients.
  • Nonlinearity: tanhf() is a rational tanh approximation that is exactly +/-1 beyond |x| = 3. ge() uses it for the positive half and 0.7*tanhf(x/0.7) for the negative half.
  • Oversampling: each input sample produces two fuzz outputs. The first uses the average of the previous and current input (linear interpolation), the second uses the input itself. A 4th-order Butterworth low-pass at 0.45 x srate (two biquads, Q 0.5412 and 1.3066, run at fs2) filters both. The first output is discarded after being run through the filter, and the second is the output sample.
  • Sag: the envelope follower tracks the post-filter signal and subtracts sg*env from the second stage's bias.
  • Adding a control: add a sliderN line at the end (so existing presets keep their mapping), compute its coefficient in @slider, and pass it through fz_set().

Dallas Arbiter Rangemaster Treble Booster

A stereo treble booster inspired by the single germanium transistor pedal behind many 1960s and 70s lead tones.

Download Dallas Arbiter Rangemaster Treble Booster.jsfx
User manual

Quick start

  1. Put it on an audio track, first in the chain, before any amp sim or other drive.
  2. Set Range for the boost and Output to match your level.
  3. Shape the tone with Input Cap and Hi-Cut, and the clipping with Bias, Germanium Asymmetry and Battery.

At defaults the small-signal response runs from about -14 dB at 100 Hz to about +9 dB at 4 kHz. Very quiet signals (-40 dBFS or lower) stay fairly clean even at full Range, while a typical guitar DI (-20 to -10 dBFS) drives the stage much harder. If it is too clean, raise Input Trim, lower Battery or raise Bias. The graph shows the linear response only, so it does not react to Bias, Asymmetry, Battery or Warmth. Feed it a DI'd guitar: the interaction with a real pickup is not modelled.

Range0 to 10Stage gain, about -4 dB to +26 dB. Also sets how hard the transistor is driven.
Input Cap (nF)1 to 100Input coupling cap. Stock is 5 nF. Try 10 to 47 nF for the "fuller" mod.

Developer notes
  • Sliders: 1 Range, 2 Input Cap (log), 3 hFE, 4 Bias, 5 Asymmetry, 6 Battery, 7 Hi-Cut (log), 8 Trim, 9 Output, 10 Warmth, 11 Oversampling index (0 to 3, factor = 2^index).
  • Memory map: 0 to 14 oversampling filter coefficients (3 biquads x 5), 100+ upsampling states (6 per channel), 120+ downsampling states (6 per channel), 200+ one-pole states (8 per channel).
  • Input network: a one-pole high-pass with rin = 59.4k || (hFE*500) and the input cap. The corner is clamped to 0.45 x srate. Output coupling is 20 nF into 150k (about 53 Hz) and also removes the DC from asymmetric clipping.
  • Clipper: sh(x, hpos, hneg) is an asymmetric tanh saturator. Headroom hp = 0.5*battery/9 and hn = hp*(1 + 1.2*asym). vb shifts the operating point and y0 is the static offset subtracted afterwards. Warmth adds 0.4*warm*v*v.
  • Oversampling: zero-stuff by osf (input scaled by osf), filter with a 6th-order Butterworth made of three biquads (Q 0.5176, 0.7071, 1.9319) at min(0.45*srate, 20000), clip, filter again and keep the first output of each group. IIR filters, so no latency is reported.
  • Smoothing: gain and output are smoothed with a 10 ms one-pole to avoid zipper noise.
  • The component values were tuned by ear. Change them in @slider (the rin, fc_out and headroom lines).

Boss CE-1 Chorus Ensemble

A chorus and vibrato inspired by the 1976 CE-1. A modulated delay line stands in for the original's bucket-brigade chip.

Download Boss CE-1 Chorus Ensemble.jsfx
User manual

Quick start

  1. Put it on track with audio content.
  2. Choose Chorus or Vibrato with Mode.
  3. Chorus: set Chorus Intensity, which sets the speed, not the depth. Vibrato: set Vibrato Rate and Vibrato Depth.
  4. Choose an Output Mode and match the level with Output.

The two modes

  • Chorus: only Chorus Intensity is active. It sets the LFO rate (about 1 to 3 Hz). The delay sweep is fixed (3 to 5 ms). The output is the direct signal plus the delayed signal, each at -3 dB.
  • Vibrato: Vibrato Rate (3.2 to 11.6 Hz) and Vibrato Depth are active. The dry signal is muted for a true pitch vibrato. At default settings the swing is roughly +/-40 cents at depth 10 and 5 Hz, and roughly +/-95 cents at depth 10 and the fastest rate.

Output modes

  • Mono Mix: one output. The stereo input is summed first.
  • Classic Stereo (default): left is the Direct output, right is the Effect output (wet only), like the original's two jacks.
  • Dual: two CE-1s, one per input channel, with LFOs 90 degrees apart. The input stays stereo.

The rate and delay ranges come from one published measurement of a single unit, so they are not verified. The advanced sliders let you match a real CE-1. The preamp is not oversampled, so very high Level or the Mic setting with a hot input can alias slightly.

Developer notes
  • Sliders (18): 1 to 4 main, 5 to 8 input and output, 9 to 11 sound character, 12 to 18 advanced tuning. Sliders are declared as slider1:mode_sw=0<...>, so each has a named variable.
  • Delay law: delay = dmin / (1 - k*u) with k = 1 - dmin/dmax and u the LFO in 0 to 1, which mimics a clock-modulated BBD (delay is inversely proportional to clock rate). Reads use 4-point Hermite interpolation in readtap().
  • Buffers: two delay lines of 16384 samples in memory (line A at 0, line B at BUFSIZE), written at wp. Line B is only read in Dual mode.
  • LFO: lfoshape(p, m) blends triangle and sine. Phase B is offset by 0.25 for Dual. Drift is a smoothed random target, redrawn every 0.3 s, scaling the rate by up to +/-5%.
  • Preamp: tanh_(x*g_pre + 0.15) minus its DC value, normalised by pnorm so small signals have unity gain. g_pre = g_sens * (level/7)^2.
  • Smoothing: rate, delay, shape and dry/wet gains use a 30 ms one-pole (smc) toward targets set in @slider, so changing mode does not click.
  • BBD filter: two cascaded one-poles at the bandwidth setting (clamped to 0.45 x srate). Noise is added before them.
  • Output: omode 0 mono mix, 1 Direct/Effect, 2 Dual. No oversampling around the preamp, which is the known aliasing limitation.

Harmony

A scale and chord processor. Each key you play becomes a chord built from a scale, and every step is adjustable: the scale, a chain of scale transforms, the chord rule, and a chain of chord transforms. A port of the "pitchwheel" web tool. The scale library comes from Francesco Balena's The Scale Omnibus.

Download Harmony.jsfx
User manual

Quick start

  1. Put it on a MIDI track before your instrument and open the editor.
  2. Pick a scale in the Scale panel using the category arrows and list, the search box, or another source.
  3. Choose an Input mode and play. With the defaults every key plays a major triad built on itself.
  4. Shape the chord in the Chord and Chord Transform panels.

Editor

The editor scales to the window. The keyboard strip shows the live scale (blue), the current chord (orange) and held keys. Values can be dragged or scrolled. Click the left or right half to step down or up, and right-click to reset to the default. In chord rule lists each number is a chip: click adds 1, right-click subtracts 1, shift-click deletes, and the + chip adds an entry. Lists hold up to 64 entries.

Input modes

  • Root: each key sets the scale root to its pitch class and plays that chord in the key's own octave. Chord Octave 4 puts a middle C chord on C4.
  • Degree: white keys play consecutive scale degrees starting at middle C (degree 0). Black keys are ignored. Chord Octave moves the starting key.
  • Direct: polyphonic pass-through.
  • Auto: play in any key. If the held keys leave the live scale, the plugin switches to the closest scale containing them all. Modal Interchange rotates through the scale's modes on the same root. Modulation keeps the mode and transposes. Distance From measures against the Original scale or the Current one (default). Autoreset returns to the initial scale on a fresh key press. The Reset button also returns to it and stops sounding chords.

In every mode except Direct each held key owns its own chord. Common Notes decides whether a note shared by two chords is held (legato) or retriggered.

The four panels

PanelContents
1 ScaleSource: Library (402 scales, 9 categories, searchable), Euclid, C-D (Clough-Douthett), Deep, or Custom (type a list or click the 12 cells). Generators use Events and, for Deep, Multiplicity.
2 Scale TransformIn order: Root, Mode (rotate the pattern on the same root), Degree (same notes from another degree), Invert (with axis), Mirror, Negative (negative harmony).
3 ChordOctave, criterion type (Position: list of degrees, default 0 2 4. Interval: stacked steps, default 2), Degree, Rotation, Voices (0 uses the list length).
4 Chord TransformIn order: Position (inversion), Offset (semitones), Mode, Invert (with axis), Mirror, Close, Spread (with top cluster), Resize (start/end), Auto-voicing. Negative picks the chord from the negative-harmony scale.

Auto-voicing picks the inversion and octave closest to the previous chord. Reset memory forgets it. Chord tones outside MIDI 0 to 127 are dropped. All other MIDI messages pass through, and CC 123 and 120 stop every chord.

Automation: all 38 settings are sliders (hidden from the default UI, shown in the editor) so they can be automated. Output Channel: Same as input or 1 to 16. The chord lists and custom scale are saved with the project and FX presets but cannot be automated.

Developer notes
  • Sliders (38): Scale source (1 to 5), scale transform (6 to 12), chord (13 to 17), chord transform (18 to 31), input and output (32 to 38). Names start with -, which hides them from the standard slider UI. Keep this order: presets and automation depend on it.
  • Pipeline: src_mask() builds the base set, mask_to_pos() gives positions, build_scale() applies the transform chain into A_SC, chord_select() picks the notes, chord_transforms() applies the chord chain, and chord_finalize() maps to MIDI notes in A_CHM. rebuild_scale() and rebuild_chord() run them.
  • Change detection: SH[] shadows every slider. handle_changes() in @block compares them and rebuilds only when something changed. Use set_sl() when code changes a slider so the shadow stays in sync and it does not count as a user edit. The GUI uses set_sl_ui(), which calls slider_automate.
  • Library: 402 12-bit masks in M_LIB, with M_CATS and M_CATN for category starts and sizes, and lib_name() as an if-chain of names. A new scale needs a mask, a name at the matching index, and updated category tables and NLIB.
  • Polyphony: V_ACT, V_CNT, V_CH and V_NOTES hold one voice per held key. O_REF counts owners per (channel, note). out_on() sends a note-on only on 0 to 1 (or always when Common Notes is Retrigger). out_off() sends a note-off only when the count reaches 0.
  • Auto mode: auto_changed() checks contains_notes() against the held-key stack, then ic_pick() (interchange) or mod_pick() (modulation) chooses by Manhattan distance. The baseline is stored by auto_enter() and restored by auto_restore().
  • Spread: EEL2 has no recursion, so spread_dfs() is an iterative backtracking search (capped at 20000 nodes, strict pass first, then relaxed). Spread works up to 16 notes.
  • Persistence: @serialize saves the three lists (A_CRP, A_CRI, A_SCP) with their lengths. lists_ver triggers a rebuild after loading.
  • GUI: @gfx 1010 530 draws at a fixed design size scaled by uis. Helpers include btn, stepper, chips, tf_run (text field) and draw_kbd. Coordinates go through fr() and ft(), which apply the scale and offset.

General developer notes

  • Each effect is one file at the top level of the repository, so installing means copying a single file.
  • JSFX uses EEL2. There is no recursion, named strings are not reachable inside functions, and slider numbers are positional, so add new controls at the end to keep saved presets valid.
  • Audio effects process per channel and compute coefficients in @slider. Anything that depends on the sample rate belongs there, because it reruns when the rate changes.
  • The oversampled effects use IIR filters and report no latency. Test changes by A/B-ing against the oversampling set to Off, and look for aliasing with a high sine sweep.
  • To report a bug, open an issue with the effect name, the settings, and a short description of what you expected.
